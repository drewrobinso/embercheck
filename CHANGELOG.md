# Changelog

All notable changes. Versions follow `VERSION` in `src/embercheck.py` (`src/bambu_optimizer.py` up to 1.4.0). EmberCheck was called **Bambu Print Optimizer** up to 1.4.0. Test numbers are from the build box (Bambu Studio 02.09.01.70 CLI slices for the H2S 0.4, six reference prints: four 225-layer towers in PLA/PETG/ABS/ASA and the 166-layer speaker adapter in PETG/ASA). Times are the optimizer's own motion model, not measured prints. Windows builds were tested under Wine 10; 1.4.2 was also installed and run on the maintainer's Windows PC.

## [1.5.0] - 2026-11-21 — PrusaSlicer and Marlin printers

### Added
- **PrusaSlicer support** (tested with PrusaSlicer 2.9.7 and the Creality Ender-3 V2 Neo profile). G-code with the Marlin 2, Marlin (legacy) or Klipper flavour is recognized from `; generated by PrusaSlicer` / the `; prusaslicer_config` block and optimized with the same goals, rules and validator as Bambu Studio G-code. See [docs/prusaslicer.md](docs/prusaslicer.md).
  - Reads PrusaSlicer's markers (`;LAYER_CHANGE`, `;Z:`, `;HEIGHT:`, `;TYPE:`, `;WIDTH:`, `;WIPE_START/END`), its config block at the end of the file (machine limits, speeds, fan, cooling, retraction, filament flow limit; mapped onto the Bambu setting names internally) and the footer estimate `; estimated printing time (normal mode)` for the raw *before* time.
  - Feature mapping: External perimeter → outer wall, Perimeter → inner wall, Internal infill → sparse infill, Solid infill → internal solid infill, Top solid infill → top surface, Bridge infill → bridge, Overhang perimeter, Gap fill, Skirt/Brim, Support material, Ironing.
  - Marlin-safe output: `M204 P<accel>` on Marlin 2 (print acceleration; `M204 S` on Marlin legacy and Klipper), `;WIDTH:` comments, no Bambu-only commands. Protected and never changed: start/end G-code, every `;TYPE:Custom` block (layer-change, colour-change, tool-change G-code), `M600`, `M601`, `M0`/`M1`, `M25`, `M125`, `M486`, `M117`/`M118`, `M240`, `M701`/`M702`, `T<n>`. Retract + wipe skips keep PrusaSlicer's wipe structure (`;WIPE_END` stays with its wipe) and also handle arc wipes.
  - Refused with a clear message (file left unchanged): binary G-code, absolute E (M82), firmware retraction (G10/G11), spiral vase, other flavours.
- **PrusaSlicer print presets.** New installer option *Add EmberCheck print presets to PrusaSlicer* (shown when `%APPDATA%\PrusaSlicer` exists; on by default): creates `<print profile> - EmberCheck Balanced / Speed / Quality` for the print profile selected in PrusaSlicer, e.g. `0.20 mm NORMAL (0.4 mm nozzle) @CREALITY - EmberCheck Balanced`. The presets carry every setting of their parent (PrusaSlicer loads user presets without resolving `inherits`), keep `inherits` for the UI and any existing post-processing script, and add the EmberCheck line. New Start menu entry *Add PrusaSlicer presets*; silent `/TASKS="prusapresets"` and `/PRUSABASE="..."`; CLI `--install-prusa-presets`, `--prusa-base "A;B"`, `--remove-prusa-presets`. A same-named preset EmberCheck did not create is never overwritten; presets you edited keep your changes (only the exe path is updated). The installer warns if PrusaSlicer is running.
- Results card, progress window, report and stamp name the slicer. For PrusaSlicer the card shows the exported file name (`SLIC3R_PP_OUTPUT_NAME`) and a *Close* button (PrusaSlicer has already finished exporting); report recommendations use PrusaSlicer's setting names.
- `test/prusa_matrix.py`, `test/test_prusa_presets.py` and `test/fixtures/prusa/` (five Ender-3 V2 Neo slices of `test/tower.stl` from the PrusaSlicer 2.9.7 CLI: PLA, PETG, M73 + Z-hop, arc fitting, Marlin legacy; `make_fixtures.sh` regenerates them).

### Changed
- The Bambu Studio preset option is only shown when Bambu Studio is installed (or PrusaSlicer is not). Uninstall entry: *EmberCheck - Print Optimizer for Bambu Studio and PrusaSlicer*.
- Uninstall also removes the PrusaSlicer presets EmberCheck created (edited ones are backed up to `preset_backups\prusaslicer\` first).
- `test/verify.py` understands PrusaSlicer files (end at the last `;TYPE:Custom`, `M204 P`, `;WIDTH:`, more protected commands, arc wipes as removable wipe moves).
- **Bambu Studio output is unchanged**: on the six reference prints × 3 goals × 3 variants (54 runs) the 1.5.0 G-code is byte-identical to 1.4.2 apart from the version in the stamp.

### Tests
- Ender-3 V2 Neo sample (PrusaSlicer 2.9.7, 500 layers, PLA, PrusaSlicer estimate 11h 59m 55s): Speed 9h 56m 24s (−17.2%), Balanced 10h 47m 30s (−10.1%), Quality 12h 03m 46s (+0.5%); validator OK and `verify.py` PASS on all three goals, also without travel re-order (strict line alignment); total E unchanged. Acceleration is already at the printer's 500 mm/s² limit and the fan at 100%, so the time comes from faster inner walls and infill (flow-limited to 15 mm³/s).
- `test/prusa_matrix.py`: 36 runs (5 fixtures + sample × 3 goals × full / no reorder) all PASS. Fixtures: Speed −10.7 to −13.5%, Balanced −6.7 to −8.4%, Quality +0.06 to +0.24%.
- `test/test_prusa_presets.py`: 25 checks PASS. Preset resolution also checked against Creality's real vendor bundle (`Creality.ini`) for the Ender-3 V2 Neo: the flattened `0.20 mm NORMAL (0.4 mm nozzle) @CREALITY` matches the settings in the sample's config block.
- Model numbers only; nothing has been printed with 1.5.0 yet.

## [1.4.2] - 2026-11-21 — renamed to EmberCheck

### Renamed: Bambu Print Optimizer → **EmberCheck — Print Optimizer for Bambu Studio**
- `EmberCheck.exe`, `EmberCheck-Setup-<version>.exe`, install folder `%LOCALAPPDATA%\Programs\EmberCheck`, Start menu folder *EmberCheck*, reports in `Documents\EmberCheck\reports` (an existing `Documents\BambuPrintOptimizer` is moved over once), window titles *EmberCheck · Print Optimizer for Bambu Studio*, presets `<layer>mm <printer> EmberCheck Balanced / Speed / Quality`.
- Python entry point `src/embercheck.py`; `src/bambu_optimizer.py` stays as a shim, so 1.x Python post-processing lines keep working.
- All links point to `github.com/drewrobinso/embercheck` (the old repository URL redirects).

### Upgrade
- **Upgrade in place** from Bambu Print Optimizer 1.x (same installer AppId): the old `Programs\PrintOptimizer` folder and the old *Print Optimizer* Start menu folder are removed; preset backups, the preset manifest and the preset log are moved to the new folder.
- The old `... AI <Goal>` and `... - Optimized` presets are backed up and retired; tweaks you made to an `AI` preset are carried over to the matching `EmberCheck` preset. Your own presets that call `PrintOptimizer.exe` are pointed at `EmberCheck.exe`, even if you untick the presets option.

### Added
- **Every Bambu Lab printer.** The installer has a printer page listing every model in Bambu Studio's own system profiles (`BBL.json` `machine_model_list`, not a hard-coded list: 15 models in 02.09.01.70) with the printers set up in Bambu Studio pre-checked. Presets are created for every nozzle each checked printer offers, each inheriting that printer's and nozzle's system process preset, with `compatible_printers` set to it (e.g. `0.20mm X1C EmberCheck Balanced`, `0.30mm X1C 0.6 EmberCheck Speed`, `0.20mm A1 mini EmberCheck Balanced`). Unchecked printers' presets are retired. Silent installs use the detected printers, or `/PRINTERS="X1C;P1S;A1 mini"`. The Start menu *Add Bambu Studio presets* re-opens the selection. New CLI flags `--printers`, `--select`.
- **EmberCheck stamp**: a `; EMBERCHECK_BLOCK_START` … `; EMBERCHECK_BLOCK_END` comment block after Bambu's header block with the version, date, goal, raw print times, per-feature savings, change counts and the SHA-256 of the rest of the file. Comments only (ASCII, < 200 characters per line); Bambu's header, thumbnails and config block stay byte-identical. New `--check-stamp FILE` (.gcode or .gcode.3mf, also checks the 3MF's plate MD5). A file that already has a stamp is never optimized again. See [docs/verify.md](docs/verify.md).
- **Raw print times** on the card headline, in the per-feature lines, the report and the stamp, e.g. `Print time: 2h 45m → 2h 29m (−16m, −9.8%)`. The *before* time is Bambu Studio's own header estimate, the *after* time that estimate scaled by EmberCheck's motion-model ratio (one model for both); without a header both are EmberCheck's model, and the source is shown. Seconds below 10 minutes.
- **Receipt log** `%LOCALAPPDATA%\EmberCheck\runs.log`: one line per optimized file (time with UTC offset, file, goal, before → after, source, body SHA-256).
- Results card: the close button is now **Continue to Print** when EmberCheck runs from Bambu Studio (it returns to Bambu Studio, which prints the optimized file), plus a one-line *How to verify* link to docs/verify.md. *Full report* is the secondary button.
- [docs/verify.md](docs/verify.md): what Bambu Studio previews, prints, sends and exports after post-processing, with source file and line references (Bambu Studio `v02.09.01.70`, `v02.08.02.61`).
- **App icon**: an original flame built from printed layer lines, heat-mapped orange → red, with a check badge on a dark tile. 16, 24 and 32 px have simplified, pixel-aligned versions (fewer, thicker lines; larger badge; no badge ring and a pixel-drawn check at 16 px). It is used for the exe, installer, shortcuts, window icon, and as a small logo on the progress window and results card. SVG sources, PNGs (16–256) and a multi-size `.ico` are in `branding/`. Three concepts are in `branding/concepts/` (B is the default); switch with `python3 branding/make_icons.py --default a|c`.
- [PRIVACY.md](PRIVACY.md) (no data collected or sent; which links open on click; local files) and [CODE_SIGNING.md](CODE_SIGNING.md) (SignPath Foundation policy: official repo, signed files, CI-only signing with per-release manual approval, roles; signing pending), linked from the README's install section and included in the Python zip with the icon assets.

### Changed
- **M73 progress (P) is now rewritten together with the remaining time (R)**, so the printer's progress bar and countdown follow the optimized print once layer 1 starts. The M73 lines inside the start G-code stay as sliced.
- **`--arcs auto` follows the target printer profile's own `enable_arc_fitting`** from the G-code (Bambu's 02.09 system profiles: on for X1C, A1 mini and other older models, off for curve-planning printers), and is always off on the curve-planning models, now including H3C and P2S.
- Acceleration, speed and fan limits were already read from each G-code's own printer and filament profile (`machine_max_acceleration_*`, fan settings), so they follow the target printer; this is now documented.
- `test/verify.py` removes the stamp block before comparing and checks `body_sha256` independently.

### Tests

## [1.4.0] - 2026-11-21

### Added
- **Smart travel order on by default** for every goal (was opt-in `--reorder`). Infill islands inside one feature are re-ordered by nearest neighbour + 2-opt; units are moved whole, never reversed. The travel time saved is now modelled and counted as credit for the goal's time limit. New `--no-reorder`. See [docs/travel-order.md](docs/travel-order.md).
- **Z-hop / retraction skip** on short infill travels (sparse or internal solid infill, layer 3+, same feature on both sides, straight path over the layer's printed area): Speed drops the spiral Z lift + lower and also the wipe + retract/un-retract pair when its E adds up to exactly 0, for travels ≤ 10 mm; Balanced drops only the Z lift/lower, for travels ≤ 5 mm; Quality keeps everything. New `--no-hop-skip`. *Why:* Bambu's H2S profile lifts and retracts before nearly every infill travel; on the PETG speaker that is ~8,100 groups. See [docs/hop-retract-skip.md](docs/hop-retract-skip.md).
- **Arc fitting** (ArcWelder-style G2/G3) with the exact decimal E sum of the replaced moves, checked against the rounded I/J centre. New `--arcs auto|on|off`; `auto` is off on printers with Bambu's curve planning (H2D, H2S, H2C, X2D, H2D Pro, A2L), where Bambu Studio also turns arc fitting off, and on for other printers. See [docs/arc-fitting.md](docs/arc-fitting.md).
- **Per-feature metrics** on the results card (travel order, hops/retracts skipped, arcs or why arcs are off) and in the report (time saved by acceleration, travel order and hop/retract skip, arcs, G-code size, M204 line count).
- **Buy Me a Coffee support**: `.github/FUNDING.yml` (`buy_me_a_coffee: drewrobinso`), a README badge and *Support development* section, and a small *Support this project* link at the bottom left of the results card that opens https://buymeacoffee.com/drewrobinso in the browser only when clicked. The link is defined once in `src/project_info.py`.
- Documentation: `CHANGELOG.md`, `docs/` with one page per optimization, README sections on the goals, features, flags, Windows SmartScreen / Smart App Control and signing, and the 1.4.0 results.

### Changed
- **Far fewer M204 lines.** The slicer's acceleration is still restored at every feature change, layer change, protected block and before any move we didn't plan, but no longer before comments, `G17`, `M73` or the slicer's own M204 lines, and a wipe block keeps the raised value when all of its moves are planned. M204 lines on Speed: PETG speaker 20,179 (1.3.0) → 3,871 (original 2,105); ASA speaker 9,347 → 3,857; PLA tower 2,842 → 2,636. No time result changed, and the acceleration at every marker is still the slicer's own.
- The time limit's re-check on the written file keeps the travel/hop credit.
- `verify.py` rewritten: own position-tracking parser, exact `Decimal` E per layer, extrusion multiset with Z, arc expansion with vertex/midpoint/direction/sweep checks (`--arc-tol`), and line-by-line alignment (without `--reordered`) that only allows removable hop/retract lines, arcs and changed F/S/M204 values.
- `test/goal_matrix.py` runs 5 variants per print and goal (full, no accel, no reorder, no hop skip, no reorder + arcs on) and writes the per-feature time table.
- The *Nothing else touched* line in the report now says that per-layer extrusion is exactly the same (instead of "no E values"), since retract pairs and arcs are merged with the exact E sum.

### Fixed (found during 1.4.0 testing, never released)
- Small arcs (r ≈ 0.65 mm) passed the fitter with the exact circle centre but were up to 0.0129 mm off after I/J rounding; the validator correctly refused the file. The fitter now checks the rounded centre with a 0.001 mm margin and also checks segment midpoints.
- A first version of the M204 reduction inserted restores inside wipe blocks after timelapse blocks; the validator refused those files (protected-block check). Fixed by treating `M73` as harmless and checking whole wipe blocks.

### Tests
- `goal_matrix.py`: 90 runs + 3 stress runs, **all rules PASS**, for the full runs and every variant. Speed: tower PLA −3.38%, PETG −7.36%, ABS −5.63%, ASA −4.67%, speaker PETG **−16.30%** (1.3.0: −6.21%), speaker ASA **−6.76%** (1.3.0: −4.19%). Balanced: −0.91% to −9.84%. Quality: −0.69% to +3.51%.
- Time saved by each feature (Speed): acceleration 0.27–4.19%; travel order −0.03% to +0.03%; hop/retract skip 0–10.05% (PETG speaker: 6,855 hops and 6,787 retracts skipped); arcs (forced on) 0.00% with 621 arcs replacing 2,787 segments on the speaker.
- 12-case regression (default and `--goal speed --fix-strings --arcs on`): all PASS with the built-in validator and `verify.py`.
- Tamper tests: arc E +0.00001, arc direction flip, one un-retract E changed: all FAIL as expected.
- `test_presets.py` OK; `ui_shots.py` 16/16 windows OK at 100/125/150/200%; `actionlint` OK.

## [1.3.0] - 2026-11-21

### Added
- **Goals with enforced promises.** Speed: model print time never above the original. Balanced: fixes most hot layers within +2%. Quality: quality first, may add time; no more hot layers than Balanced, at least as many overhang slowdowns. Ordering t(Speed) ≤ t(Balanced) ≤ t(Quality). Speed and Balanced fix hot layers with fan first (free), then drop the lowest-value slowdowns to keep the limit, re-checked on the written file; unfixed hot layers become the first recommendation. `--no-time-limit` restores the old behaviour. *Why:* in 1.2.1 Speed could end up slower than the original (speaker ASA +0.03%).
- **Speed-aware acceleration** (M204) per feature: sparse/internal solid infill and inner walls up to the machine maximum (Speed), ×1.5 (Balanced), infill-only ×1.2 (Quality). Never on outer walls, overhangs, bridges, top surfaces, the first 3 layers, hot layers or protected blocks; the slicer's value is restored at every feature/layer change and protected block, modelled for M73, and validated. Shown separately on the card and report. `--no-accel`.
- `test/goal_matrix.py` (rules on all six prints) and `test/ui_shots.py` (windows at 100/125/150/200%).

### Fixed
- **Buttons cut off on the results card at Windows display scaling** (reported as "Buttons are cut off, can't see which option i'm clicking!"). The windows are now DPI-aware (`SetProcessDpiAwareness`), Tk scaling follows the monitor DPI, buttons size to their text, the bottom row is packed first, the recommendations scroll, and the window is capped to the screen. This was planned as 1.2.2 and shipped in 1.3.0 instead.

### Tests
- Goal matrix: all rules PASS. Speed: tower PLA −3.02% (1.2.1: −0.81%), speaker ASA −4.19% (1.2.1: +0.03%), speaker PETG −6.21%. Balanced ≤ +2% on all prints. Stress cases (only slowdowns available): Speed +0.00%, Balanced +1.78%.
- `ui_shots.py`: 16/16 windows OK. 12-case regression with `verify.py`: PASS.
- Installer `PrintOptimizer-Setup-1.3.0.exe` (unsigned local build), SHA-256 `f852be624c9d27f087748532a5ddf30cf3b01d55e28114295e5c394e8229697b`.
